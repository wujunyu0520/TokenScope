# TokenScope 用量数据对账验收报告

## 技术结论

截至 2026 年 7 月 12 日 00:03（北京时间），TokenScope 的 Claude Code 与 Codex 核心用量口径已完成本机真实数据对账。

- Claude 的小型会话、最大会话、最近 7 天、全部历史和最近有效会话，五项 Token 均可逐整数闭合，允许误差为 0。
- 审计发现并修复了“最近会话”按开始时间选择的问题；修复后改为按最后一条有效 usage 时间选择。
- Codex 的五小时与每周窗口来自 OAuth 官方接口；紧邻刷新时，重置时间完全一致，使用率差异不超过 1 个百分点。
- Claude 的“全部会话”定义是本地历史缓存，不等同于当前仍存在的 JSONL 文件总和；差异已通过缓存历史与重复日志的逐条 usage 序列去重完整解释。
- 成本区域仍是本地会话与内置价格估算，不属于本报告的官方账单对账范围。

本次验收状态为 **PASS**。仍保留一个低风险工程项：subagent 会话 ID 只使用文件名，跨目录同名时可能碰撞。

## 验收标准

| 检查 | 允许误差 | 结果 |
|---|---:|---|
| Claude 单会话五项 Token | 0 Token | PASS |
| Claude 全部历史、最近 7 天、最近有效会话 | 0 Token | PASS |
| Codex 固定夹具的蛇形窗口字段解码 | used_percent、reset_at、窗口长度逐值一致 | PASS |
| Codex 页面缓存与相邻官方请求 | 缓存不超过 60 秒、同账号、最多 1 个百分点、重置时间 0 秒 | PASS |
| 页面重置倒计时 | 目标最多 60 秒 | 人工界面验收；脚本核对绝对 reset_at |
| Codex 成本 | 不适用 | 明确标注为本地估算 |

Codex 使用率允许 1 个百分点的相邻请求误差，是因为当前 Codex 会话本身会持续消耗额度；窗口 `reset_at` 不允许漂移。自动门禁还要求页面缓存与官方请求相隔不超过 60 秒，并通过 OAuth `account_id` 的不可逆 SHA-256 指纹证明是同一个额度账号；邮箱只作为辅助诊断，不参与严格 PASS。若官方窗口发生切换，必须先刷新应用，再按新窗口重新比较。页面倒计时文本属于人工界面验收，自动门禁比较的是绝对 `reset_at`。

## Claude 的真实日志解析准确

本机共扫描 489 个 Claude JSONL 文件：394 个包含正 Token，95 个没有正 Token 并被排除；文件级扫描异常为 0，当前正用量 session ID 在生产缓存中的缺失数为 0。生产 scanner 与独立逐行解析结果数量一致。

| 真实样本 | 正用量记录数 | 总 Token | 独立解析与生产缓存 |
|---|---:|---:|---|
| 小型有效会话 | 2 | 54,476 | 五项差异均为 0 |
| Token 最大会话 | 1,100 | 477,773,908 | 五项差异均为 0 |
| 7 天边界最近替代会话 | 750 | 259,252,966 | 五项差异均为 0 |

真实日志中没有单个会话同时跨越本次 7 天边界两侧。为避免把“未找到样本”误判为“未验证”，额外使用固定夹具：边界前 1 秒与边界后 1 秒各一条记录。生产实现只纳入边界后的记录，最近 7 天总量为 328 Token，与独立计算完全一致；边界条件为闭区间。

## 全部历史与当前磁盘日志的差异可完整解释

TokenScope 会保留已经进入 v2 缓存、但当前磁盘扫描不再出现的历史会话，同时按稳定会话 ID 去重重复日志。因此“全部会话”是本地历史口径。

当前数据的闭合公式为：

```text
当前 394 个有效 JSONL 的直接合计       2,896,638,455
- 一份重复日志副本                         68,982
+ 6 个仅存在于缓存的历史会话             10,076,497
= TokenScope 全部历史                  2,906,645,970
```

净差异为 10,007,515 Token，各分项与上述公式均精确闭合，公式残差为 0。最近 7 天与最近有效会话没有 cache-only 差异。

这不是 Token 解析错误，但产品含义需要保持明确：

- “全部会话 / 本地历史”包含已从当前日志目录消失的缓存历史。
- “最近 7 天”按每条 usage 的时间戳滚动计算。
- “最近会话”按最后一条有效 usage 时间选择。

| 窗口 | 官方 used | 页面缓存 used | 差异 | 官方剩余 | 窗口长度 | reset_at |
|---|---:|---:|---:|---:|---:|---|
| 五小时 | 44% | 44% | 0 | 56% | 18,000 秒 | 完全一致 |
| 每周 | 7% | 7% | 0 | 93% | 604,800 秒 | 完全一致 |

两个窗口的官方与缓存重置时间分别为 2026 年 7 月 12 日 04:27:10 和 7 月 18 日 23:27:10（北京时间），秒级一致。人工界面验收过程中，应用还经历了一次官方窗口切换；旧窗口达到 100% 后，刷新成功切换到新窗口，页面没有继续展示旧的 reset 时间。

机器快照显示凭据来源为 OAuth `tokens`，且未发现可用 API Key（`api_key_present=false`）。仓库固定夹具另行覆盖“OAuth 与非空 API Key 同时存在”场景，验证 OAuth 优先级。

## 方法、隐私与可重复执行

审计脚本只输出哈希会话标识、计数、Token 汇总、窗口百分比和时间；不会输出消息正文、完整日志路径、邮箱、Access Token、Refresh Token、API Key 或 Authorization 请求头。实时 Codex 请求固定到 `https://chatgpt.com/backend-api/wham/usage`，忽略环境中的自定义基址并拒绝 HTTP 重定向，避免 OAuth 凭据被转发到其他主机。

最终 `PASS` 还要求：文件级扫描异常为 0、当前有效 raw 会话均进入缓存、重复 ID 文件的逐条 usage 时间与五项 Token 序列不存在冲突、历史闭合公式残差为 0；Codex 缓存不超过 60 秒且 OAuth `account_id` 指纹与缓存快照一致。指纹使用完整域分隔 SHA-256，原始账号 ID 和指纹都不会写入机器证据。缺失文件、损坏的必需缓存 JSON 或网络错误只返回不含路径、URL、响应正文和异常堆栈的结构化错误码。

本报告对应的脱敏机器快照保存在 `docs/evidence/usage-data-reconciliation-2026-07-11.json`。

先在 TokenScope 用量页刷新 Claude 与 Codex，然后运行：

```bash
python3 Scripts/audit_usage_data.py \
  --live-codex \
  --output /tmp/tokenscope-usage-audit.json
```

退出码 `0` 表示 Claude 样本、窗口与历史闭合，以及 Codex 官方窗口、缓存新鲜度和账号来源全部通过；退出码 `2` 表示需要查看差异。页面倒计时文本不在脚本自动验收范围。若 Codex 官方窗口刚刚切换或页面缓存较旧，应先刷新应用，再重新执行。

审计脚本回归测试：

```bash
python3 -m unittest discover -s Tests/ScriptTests -p 'test_*.py'
```

该测试已加入 `Scripts/verify_release.sh`，GitHub `quality-gate` 会与 Swift XCTest、中文检查、Release 构建、打包和严格签名一起执行。

## 限制、后续监控与建议

1. 本机没有完整 Xcode，正式 `swift test` 会在执行测试前报 `XCTest not available`；GitHub macOS Runner 是正式发布门禁。
2. 一个真实 subagent 会话 ID 出现两份日志副本。本次两份 usage 序列一致，缓存去重正确；未来应把父会话或相对目录加入 subagent ID 命名空间。
3. 建议在“全部会话”旁增加“含缓存历史”说明或查看入口，让用户可以区分当前文件与本地历史。
4. 每次修改 Claude 解析、缓存合并、Codex OAuth 或额度窗口后，重新运行本报告对应的审计脚本并保存新的时间戳快照。

进一步需要产品决定的问题只有一个：是否提供“清理已删除日志对应的历史缓存”按钮。当前报告按既有“本地历史”语义验收，因此不自动删除这 6 个历史会话。
